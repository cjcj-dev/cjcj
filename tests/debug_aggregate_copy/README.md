# Generic aggregate debug copies

`run.py` invokes the real stage1 compiler on the local `Offset<T>` fixture and a
scalar control, with and without `-g`. It retains raw bitcode with `--save-temps`
and independently feeds each module to the product `opt` bitcode reader.
Presence, reader acceptance, and driver completion are reported separately;
compiler failure never prevents the reader assertion from running on emitted
bitcode. `-disable-verify` isolates the bitcode reader's explicit-GEP-type check
from subsequent optimization or verification passes.

With `--runtime-dir`, the runner also compiles and executes `value.cj` with `-g`.
The generic struct, its methods, and its instantiations belong to this input,
so the value assertion observes code generated by the compiler being tested.
A missing executable is `NOT_RUN`, not a runtime-value failure.

Example (use a matching target std/runtime and the stage1 compiler's host runtime
in the compilation environment):

```sh
cjHeapSize=32GB python3 tests/debug_aggregate_copy/run.py \
  --compiler "$SDK/bin/cjcj-stage1" --opt "$SDK/third_party/llvm/bin/opt" \
  --runtime-dir "$SDK/runtime/lib/linux_x86_64_cjnative" \
  --jobs "$(nproc)" --workers 1 --out "$EVIDENCE"
```

Use separate output and SDK directories for parallel arms. When comparing four
compiler arms concurrently, `--workers 1` keeps the total at four compiler
processes. Every invocation writes input, compiler, LLVM reader, runtime and
result hashes plus affinity, elapsed time and both uptime readings.

Fault controls: bypass the source-address cast in `CopyNativeAggregate`, or
replace the `StoreStructManagedMemberValue` consumer's `CopyNativeAggregate`
call with `CopyAggregateTyped`. Both should reject only the generic debug
bitcode; both scalar controls and the non-debug generic input must still pass.
Restore the compiler artifact and run the unchanged inputs again.

The production fix preserves the original address, as the upstream memcpy does
(`CodeGen/CJNative/CJNativeIRBuilder.cpp:837-847`). Debug boxing already produces
a payload address before casting it to pointer-to-argument type
(`CodeGen/IRBuilder.cpp:379-385`); that cast must not be interpreted as an extra
load or unboxing operation.
