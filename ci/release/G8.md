# Capturing the full gate

Run from a checkout with the compiler package artifacts in `target/release`:

```sh
ulimit -c 0
node ci/release/g8.mjs --sdk /absolute/deployed-sdk --out /absolute/new-campaign-directory
node ci/write-full-gate-floor.mjs --results /absolute/new-campaign-directory/G8_FULL_GATE.json --out /absolute/staging/full-gate-release-floor.mjs
```

The producer runs difftest, smoke, bcgate and source-build verify concurrently,
with separate temporary directories. It selects the official comparison SDK
from `ci/host_sdk_pin.env`, explicitly supplies both difftest compilers, and
records compiler/runtime hashes, commands, exit codes, signals and raw stdout
and stderr hashes. The existing corpus tools currently support Linux x64.
`verify` also needs this checkout's compiler package artifacts; an SDK alone
does not supply them. The SDK must satisfy the existing packaged-lineage check.

The output directory must not exist. Missing, repeated, empty or inconsistent
summaries do not become zero counts. All four commands are attempted; an
incomplete or failing run is archived and exits nonzero. A successful capture
is eligible for floor writing, not an assertion that the release is approved.
Use `ci/release-gates.mjs G8 --evidence DIR --json` against the approved floor
to apply release comparisons. The producer does not modify or commit that floor.
Release control owns the ordering of the floor commit and the frozen head.

After retaining logs and failure artifacts, remove successful run intermediates
(`*-tmp`, `smoke-work`) according to the campaign's storage policy.
