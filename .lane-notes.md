# cjcj#340 fast-math IR flags

Upstream (cangjie_compiler, not ZGC):

- `src/CodeGen/IRBuilder.cpp:17-23` `IRBuilder2(CGModule&)` writes `FastMathFlags::setFast(true)` then `setFastMathFlags` when `fastMathMode`.
- `src/CodeGen/IRBuilder.h:32-38` `IRBuilder2(CGModule&, BasicBlock*)` does the same after the base constructor positions the builder.
- LLVM print: `llvm/lib/IR/Operator.cpp:230-232` emits ` fast` only when `all()` is true.
- `setFast` is `llvm/include/llvm/IR/FMF.h:98`.

Ours:

- `runtime_shim/cjselfhost_llvmshim.cpp` `LLVMSelfhostBuilderSetFastMath` calls `unwrap(builder)->setFastMathFlags` after `fmf.setFast(true)`. `LLVMBuilderRef` unwrap is `DEFINE_SIMPLE_CONVERSION_FUNCTIONS(IRBuilder<>, LLVMBuilderRef)`.
- `packages/codegen/src/LLVM.cj` foreign `LLVMSelfhostBuilderSetFastMath`.
- `packages/codegen/src/IRBuilder.cj` both `init`s call it under `GetCompileOptions().fastMathMode`. The block-taking init sets the flags after `LLVMPositionBuilderAtEnd`, matching the upstream body-after-base order.
- `ApplyFastMathIfNeeded` and its four call sites are deleted. FP instructions take the builder default via `LLVMBuildF*`.

Do not call `LLVMSetFastMathFlags` (declared, not exported by LLVM 15 C API).
